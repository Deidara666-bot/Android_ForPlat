## v0.30.5 — Unggah, hash ulang server, tolak mismatch, simpan imutabel (KONTRAK §W)
Butuh: v0.30.4 · Env: semua hidup · Kelas: **kontrak**

Kontrak (urutan mengikat): `Acquire → Write raw → SHA-256 agen → Upload → SHA-256 server → Compare → Store immutable`.
Server tidak pernah menyalin `sha256_agent` ke `sha256_server`. Mismatch → ditolak + tercatat.

Kerjakan:
1. `agent/src/transport/uploader.py`: multipart `POST /api/evidence/upload` (agent token) berisi file bytes
   apa adanya + `session_id`, `operation_id`, `sequence` (dari job), `part`, `sha256_agent`, `size_bytes`, `acquired_at`,
   `tool_version` (adb), `android_version`, `device_build`, `privilege_state`. Runner memanggilnya setelah hash.
2. `backend/app/api/routes/evidence.py` `POST /api/evidence/upload` — urutan:
   terima bytes → validasi (ukuran ≤ 50 MiB, `size_bytes` = panjang nyata, `(sequence, operation_id)` cocok baris
   `acquisition_operations` sesi itu) →
   `IntegrityService.sha256_bytes` → banding:
   - cocok: `EvidenceStorageService.store(...)` → baris `evidence` `availability_status=acquired`, dua hash terisi;
   - beda: berkas **tidak** disimpan; baris `evidence` tetap dibuat dengan kedua hash (berbeda),
     `availability_status=failed`, `availability_reason="sha256 mismatch"`, `stored_path` NULL. Respons 422.
3. `backend/app/services/evidence_storage_service.py` `EvidenceStorageService.store(session_id, sequence, operation_id, part, data)`:
   path = `EVIDENCE_ROOT/<session_id>/<sequence>-<operation_id>-<part>.bin` disusun server (⛔ nama dari klien diabaikan),
   `resolve()` harus tetap di bawah `EVIDENCE_ROOT`, tulis mode `"xb"`, lalu set read-only (`chmod 0o444`).
4. `source_group` diisi dari REF §OPS; `raw_source` = nama sumber (`getprop` / `pm list packages -U`);
   `source_name` = operation_id.
5. Test `backend/tests/integration/test_evidence_upload.py`: cocok → tersimpan & dua hash sama; hash palsu →
   422, baris `failed` dua hash beda, tidak ada berkas; unggah kedua sesi/sequence/part sama → gagal, berkas lama utuh;
   filename klien `../../evil.txt` → tidak ada berkas di luar root; `size_bytes` salah → 422.

Jangan: endpoint yang menimpa/menghapus bukti. Menyimpan bukti di dalam repo selain `backend/var/evidence`.
File: berkas langkah 1–5
Cek: `check.sh all` → OK; setelah satu akuisisi nyata:
`psql -c "select sha256_agent=sha256_server, availability_status from evidence order by acquired_at desc limit 1"` → `t|acquired`;
`sha256sum` berkas di `agent/var/raw/...` = berkas di `backend/var/evidence/...`.
Uji gagal: `git check-ignore -v backend/var/evidence agent/var/raw` → keduanya cocok aturan `.gitignore`;
test hash-palsu & path-traversal di atas harus lulus (dan gagal bila perbandingan dihapus — cukup dijelaskan di laporan).
Commit: `feat(integrity): verify sha256 server-side and store raw evidence immutably [v0.30.5]`
Ref: §W, §Y.1, §20, §AD, §B prinsip 4
