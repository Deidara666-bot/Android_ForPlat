# Matriks uji unit v0.60 — kelas skenario A–F

Dihasilkan dari `backend/tests/scenarios/catalog.py` (kartu `v0.60.9`). Tiap skenario adalah rantai bukti
sintetis (pabrik `tests/factories.py`) yang dijalankan lewat `RuleEngine` dan YAML aturan asli, lalu
dibandingkan dengan **oracle** yang ditulis dari aturan dan semantik REF §ENGINE, bukan disalin dari
keluaran mesin. Bentuk fakta = keluaran penormalisasi produksi; satu-satunya penyimpangan sengaja adalah
kelas E (konflik sintetis: fakta positif dan negatif untuk satu nilai) dan kelas F (klon profil di memori
dengan kondisi eksklusioner penanda, tidak pernah ke basis data atau YAML).

Tidak ada angka agregat di dokumen ini: tiap baris adalah satu kasus, bukan sampel statistik.
Semua kondisi tiap run, bukan hanya yang diberi oracle, ikut diuji pada invarian pencatatan: kondisi
terpenuhi/tidak terpenuhi menaut ≥1 fakta; kondisi tidak diketahui menaut nol fakta dan beralasan;
temuan ada tepat untuk profil terpenuhi; ringkasan temuan tanpa kata vonis.

Menjalankan: `python -m pytest tests/scenarios` dari `backend/`.

## Skenario per keluarga

Kolom *Profil* memakai padanan terkunci: terpenuhi / tidak terpenuhi / bukti tidak memadai; *tidak berlaku*
= profil dilewati (`skipped_not_applicable`) pada mode itu. Kolom *Kondisi yang diperiksa* hanya memuat
kondisi yang menjadi pokok kelas itu.

membacanya dari berkas aturan dan dari daftar fakta bernegatif eksplisit (v0.45.7).

| Keluarga · kelas | Alasan |
|---|---|
| K04 · B | Tidak ada kondisi wajib yang bisa tidak terpenuhi: fakta identitas, pemakaian, activity, dan proses tidak punya negatif eksplisit. |
| K05 · A, B, C, D1, E, F | Setiap profil butuh fakta tanpa produsen (jaringan UID, titik akhir lokal, pengikatan skenario): kondisi wajibnya selalu tidak diketahui (`not_acquired`, atau `coverage_incomplete` bila butuh jendela run), sehingga keluarga ini hanya bisa `bukti tidak memadai`. Kelas D2 terjangkau dan ada skenarionya. |
| K01-P03 · B (statis) | Izin yang dideklarasikan APK tidak punya fakta negatif eksplisit. Kelas B keluarga K01 tercakup oleh profil runtime. |
| K02-P04 · B (statis) | Deklarasi akses khusus statis tidak punya fakta negatif eksplisit. Kelas B keluarga K02 tercakup oleh profil runtime. |

Produsen fakta jaringan dan pengikatan skenario menyusul di `v0.70`/`v0.80`; saat produsen ada, entri K05
dipindah dari daftar ini ke katalog.

## Determinisme (§18.3a)

`app/research/consistency.py` `semantic_snapshot(db, run_id)` mengembalikan data JSON terurut yang memuat enam
butir §18.3a: (1) kunci dan keadaan tiap kondisi; (2) alasan kondisi tidak diketahui dan id fakta konflik;
(3) fakta penopang tiap kondisi; (4) versi, status, dan hash isi aturan serta keluaran tiap evaluasi;
(5) ada/tidaknya temuan dan isinya (hipotesis menyusul di `v0.70`); (6) relasi keterlacakan kondisi → fakta →
artefak. Id run, id baris evaluasi, dan cap waktu basis data sengaja tidak masuk.

`tests/scenarios/test_determinism.py`: tiga run atas masukan sama (runtime berjendela dan statis) menghasilkan
snapshot identik; snapshot memuat ketiga keadaan, sebuah konflik, dan temuan, jadi bukan perbandingan kosong;
satu fakta baru mengubah snapshot (kontrol).
